# Shared Graph City / HubSide conversation

Fidget reuses the existing `wss://24.144.88.205/multiplayer` service, `morning-quarter-v1` room and `map2-v1` world. No server is created or modified. Reference: `benryaus-cmd/graf-game`, fetched October 14, 2026, HEAD `5ac7f8e`. Configuration, protocol handshake, profile fields, admin action builders and server permission parsing match the reference source.

`src/chat/useChat.ts` exports `useChat()`. It returns `messages`, `status`, `unread`, `profile`, `isOwner`, `error`, `send(text)`, `markRead()`, `moderate(action, targetUsername, options)` and `reconnect()`, plus `players`, `mute`, `historyReceived`, `moderationResult`, and `profileLoading`. `ChatPanel` is a default export with `{ mode: 'overlay' | 'room', onClose }`. Header and panels subscribe to one shared socket. Mounting a panel marks messages read; live messages increment unread only when panels are closed. Toy keyboard handlers ignore text inputs and chat/dialog targets; chat stops key propagation so typing never triggers piano notes. Pending physical toy outcomes still finish and score normally. The overlay is positioned within `.uff`, clears its header/navigation, and computes keyboard occlusion relative to that host’s actual bounds. The full room uses its parent’s available height, constrained by the visible viewport bottom. `ResizeObserver` and `visualViewport` resize/scroll events update geometry without redundant state updates and keep the log at the bottom.

The Aippy SDK supplies `uid`, `username`, `nickName`, and `avatar`. A socket opens only after the SDK provides a real uid and username; standalone browser previews show the profile-required state. Username and nickname are transmitted as supported by the original protocol. UID scopes the local cache but is not invented or sent as an unsupported authentication field. The SDK avatar is shown for the current user. Legacy message bodies borrow missing username/nickname/avatar fields only from the exact matching player ID in the current server directory; unknown/departed IDs remain unknown. Existing explicit message identity fields are retained. Other profiles use server-provided usernames/nicknames and, when actually supplied in the directory/message, validated HTTP(S) avatar URLs; otherwise they use initials. The reference does not promise avatar delivery, so no profile lookup endpoint is invented.

Protocol 2 waits for `hello`, advertises network revision 6 and the same required capabilities as Graph City, then joins the same room/world with finite initial position `[0,0,0]`. Admission requires a matching `world_snapshot`; early `permissions` and `chat_mute_state` are queued with a small bound and released only after valid admission, never granting owner UI while connecting. The queue clears on disconnect/new connection. chat sends only on an explicit Send/Enter action and uses `{ type: 'chat_message', text }`. The chat-only client does not send movement, painting, gameplay rewards, purchases or credit actions. Automatic pong and reconnect after ordinary transport loss use the existing protocol. Explicit kick/ban/admission rejection does not automatically rejoin.

## History boundary

The verified bootstrap is `world_snapshot.chatHistory`. Fidget merges it with this account’s local cache, deduplicates by message ID and filters to the last hour. Memory/cache have a 2,000-message safety bound. While an SDK profile is identified, a 30-second prune timer expires old messages and corresponding unread IDs from the store and local cache even when offline or no new frame arrives. The store retains the last known server clock offset across transport loss. The timer clears on profile removal/replacement; explicit server removal still clears owner rights and never automatically rejoins. The reference client retains only its last 100 snapshot messages. No verified one-hour history query exists in the source or production hello capabilities. A fresh device therefore cannot guarantee recovery of every message in a busy hour; the UI explains that older messages may be unavailable. No fabricated endpoint, unsupported history request or claim of complete server-side hourly retention is used.

## Shared moderation and identity boundary

Owner controls appear only after the server sends `permissions` with `role: 'owner'`. The nickname, known owner username (`moodytag_4g3b`) and local profile never independently grant rights. Actions target the shared username and use the reference wire formats: `admin_kick`, `admin_ban` (`durationSeconds`), `admin_unban`, `admin_mute` (`durationMinutes`), `admin_unmute`. Ban/unban remain pending until the supported server completion arrives. Kick/mute/unmute report Requested because the reference documents no acknowledgment format for those requests; no success acknowledgment is invented. Relative mute countdowns use the same local clock for state receipt, UI and send gating so server clock skew does not extend them. Server errors, mute state, kick and ban messages are handled; shared enforcement remains the existing server’s responsibility.

The reference `accountFeatures.ts` explicitly documents deployed `AIPPY_AUTH_MODE=disabled`. This client can preserve server-assigned roles and native SDK profile presentation; it cannot make the existing service verify Aippy account ownership or guarantee resistance to impersonation. Authentication hardening or guaranteed full-hour retention would require changes to the existing backend and cannot honestly be claimed by this client-only integration.

## Verification

`node src/chat/chat.test.mjs` checks the exact mock hello/join frames, matching room/world admission, user-triggered sends and rate limit, owner permissions versus forged nickname, moderation payloads, server mute state, ping/pong, unread state, one-hour cache merge and malformed-message rejection. Tests never send real chat or moderation. TypeScript validation: `npm run typecheck`.

A read-only production socket probe on October 14, 2026 received protocol 2 `hello`, minimum network revision 6, and required capabilities `spatial_interest_v1`, `spatial_world_delta_v1`, `player_directory_v1`. The probe closed immediately without a join, message or moderation action. Live account admission/history delivery requires the native Aippy profile and was not fabricated in a standalone test environment.
